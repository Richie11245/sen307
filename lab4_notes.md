# Lab 4 Notes: Referential Integrity

In Part 4, deleting the "Library and Information Science" department failed with **Error 1451: Cannot delete or update a parent row: a foreign key constraint fails**. MySQL refuses because the `Student` table still contains a row (`Transfer Student`, matric 20239999) whose `dept_id` points to that department. Deleting the parent row would leave an orphaned student referring to a department that no longer exists, so the foreign key constraint protects the database's referential integrity. I fixed it the correct way: first I used `UPDATE` to reassign the dependent student to the Software Engineering department, and then the `DELETE` succeeded, leaving 5 departments with the student moved rather than lost. Other fixes would have been to delete the dependent student first, or to define the foreign key with `ON DELETE CASCADE` (which automatically deletes the dependent students too, risking accidental data loss) or `ON DELETE SET NULL` (which keeps the student but clears their department, provided `dept_id` allows NULL).
